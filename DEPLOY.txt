NUKETOWN — Vercel deploy package
================================

WHAT THIS IS
  The complete, ready-to-serve web build of the game. public/ already contains
  the bundled JavaScript, the compressed .glb models, the textures, the fonts and
  the offline cache — nothing needs to be compiled to run it. src/ and scripts/
  are here only so you can rebuild if you edit the game.

  ~7.5 MB total. No backend, no database, no server to keep running.


DEPLOY (takes about a minute)
  1. Install Node.js once, if you do not have it:  https://nodejs.org  (any v18+)
  2. Open a terminal IN THIS FOLDER and run:

         npm install -g vercel
         vercel --prod

  3. First run asks you to log in (it opens a browser) and to confirm the project
     name. Then it prints a live link like:

         https://nuketown-abc123.vercel.app

     That URL is the game. Anyone can open it in Chrome or Edge, click Deploy, and
     play. No download, no install, no account for the player.

  Re-run `vercel --prod` after any change to publish it.

  NOTE on rebuilding: this package ships the built output plus src/js, src/index.html
  and src/fonts, but not the 13 MB of asset masters under src/assets (the compressed
  versions in public/ are all that is needed to play). To run `npm run build` from
  scratch, clone the git repo instead.

  ALTERNATIVE (git, better if you will keep editing): push this folder to a GitHub
  repo, then on https://vercel.com choose Add New > Project > Import that repo and
  click Deploy. vercel.json already sets framework "Other", no install step, no
  build step, output directory public — there is nothing to configure.


IF YOU ONLY WANT TO SEE IT ON YOUR OWN MACHINE
         npm install          (only needed to rebuild, not to play)
         double-click START.bat
     ...or:  node scripts/serve.mjs   then open http://localhost:8420


LINK PREVIEWS (optional polish)
  The card people see when the link is pasted into Discord or X points at
  https://YOUR-APP.vercel.app by default. To make it exact, set that before
  rebuilding:

         set PUBLIC_URL=https://YOUR-APP.vercel.app
         npm install
         npm run build

  ...then `vercel --prod` again. public/og.png is a real screenshot of the menu,
  generated by: npm run og


PLAYING / CONTROLS
  WASD move · mouse look · LMB fire · RMB aim · Shift sprint · Ctrl/C crouch ·
  Space jump · R reload · 1-4 weapons · Z/X UAV + Airstrike · V Tactical Nuke
  (15 kills, Team Deathmatch) · Tab scoreboard · Esc pause · F performance readout

  Needs a keyboard, a mouse and WebGL2 — a laptop or desktop browser. Chrome or
  Edge are best. It starts on Low quality and raises itself if your machine has
  headroom.

  Phones and tablets are not supported and there is no touch mode: opening the
  link on one shows a "Not available on mobile" panel with Deploy disabled, so
  nobody clicks into a match they cannot aim in. Nothing else changes — the same
  URL serves both.

  Modes: TEAM DEATHMATCH (5v5, respawns, first to 75) and ROUND CONTROL
  (3v3, one life per round, first to 3, spectate teammates when you die).


CHECKING A BUILD (optional)
         npm install
         npm i -D puppeteer
         npm run build
         node scripts/serve.mjs &
         npm run verify

  verify.mjs boots the built page in a real Chromium and fails if there is any
  console error, 404, missing model, or if the second visit still hits the
  network. Point it at your deployment with:
         VERIFY_URL=https://YOUR-APP.vercel.app node scripts/verify.mjs


WHAT CHANGED vs. the offline Windows build
  - three.js and all 21 game modules are bundled into ONE file instead of being
    fetched as 21 separate requests plus a cold CDN hop for the engine.
  - The .glb soldiers, weapons and hands are quantised and Meshopt-compressed:
    8.2 MB of models down to 4.2 MB. Any file that fails to read falls back to the
    procedural mesh it was authored against, so a bad asset can never break a match.
  - Photo textures re-encoded 3.8 MB -> 1.9 MB. The 10.3 MB of uncompressed art
    reference sheets were never needed at runtime and are not deployed.
  - Menu fonts self-hosted instead of render-blocking Google Fonts.
  - A service worker caches the game: first visit costs 4.8 MB, every visit after
    costs 0 bytes on the wire, and the match still loads with no internet at all.
  - Model downloads now start before the map builds, and shaders are pre-compiled
    while the loading bar is up, which removes first-match hitches.


NOTES
  - public/ is the deployable output; it is committed on purpose so a Vercel
    deploy is a plain file copy with no build that can fail.
  - vercel.json deliberately sets no X-Frame-Options, so the game can be embedded
    in a page. Add { "key": "X-Frame-Options", "value": "DENY" } to the
    "/(index.html)?" header block if you would rather not.
  - Single-player with bots: the whole game runs in the browser, so there is
    nothing to host beyond the static files, and no cost beyond Vercel's free tier.
